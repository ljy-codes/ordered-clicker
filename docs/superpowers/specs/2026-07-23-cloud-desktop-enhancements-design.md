# 有序连点器云桌面增强版设计

## 1. 背景与目标

当前连点器运行在本机 Windows，实际操作对象位于“本机浏览器 -> 云桌面 -> 公司业务系统”中。现有实现直接保存并回放本机屏幕绝对坐标，适合普通桌面应用和布局固定的简单流程，但存在以下问题：

1. 浏览器位置、工具栏高度、云桌面画面尺寸或鼠标模式变化后，绝对坐标可能偏移。
2. 当前快捷键必须包含修饰键，零基础用户操作较复杂。
3. 当前只有按方案名称保存覆盖，没有明确的“另存为”入口。
4. 执行前不显示总行数和启用点数，执行完成也不显示实际明细，用户无法判断为什么只执行了前两个点。
5. 云桌面页面加载时间不稳定，单纯使用固定等待时间容易提前点击下一步。

本版本目标是增加一个可选的“云桌面增强模式”，提高浏览器云桌面场景下的位置稳定性、长流程可观察性和操作易用性，同时保持旧方案兼容。

## 2. 范围

### 2.1 本次实现

- 云桌面区域两点标定。
- 相对云桌面区域的点位坐标。
- 使用 `SendInput` 绝对虚拟屏幕坐标移动鼠标，并验证实际落点。
- 可选的画面稳定等待。
- 画面稳定等待超时时暂停，由用户选择继续或停止。
- 执行前计划确认和执行后结果明细。
- 多步骤流程完整性校验、执行日志和中断点继续。
- 简洁快捷键与兼容快捷键预设。
- 增加“另存为”。
- 更新自动化测试、HTML/PDF 使用说明、安装包、便携包和产品目录。
- 版本升级到 `1.3.0`。

### 2.2 不在本次范围

- 不识别网页 DOM、按钮文字或控件结构。
- 不实现 OCR、模板图片匹配或目标按钮自动搜索。
- 不绕过云桌面、浏览器或公司系统的安全限制。
- 不保证在浏览器启用指针锁定、远程系统拒绝模拟输入或页面持续动画时完全自动执行。
- 不修改现有视频教程。

## 3. 方案选择

采用“区域相对坐标 + 绝对鼠标输入 + 画面稳定检测”的组合方案。

与纯绝对坐标相比，重新标定云桌面区域后，所有点位可按区域比例自动换算，不需要逐点重采。与完整图像识别相比，该方案配置更简单、性能开销更低，也更适合当前 WinForms 工具的边界。

## 4. 数据模型

### 4.1 方案版本

`ClickProfile.Version` 从 `2` 升级为 `3`。

加载规则：

- `Version <= 2`：按绝对屏幕坐标加载，云桌面模式默认关闭。
- `Version == 3`：根据 `CoordinateMode` 决定使用绝对坐标或区域相对坐标。
- 保存时统一写入版本 `3`。

### 4.2 坐标模式

新增：

```csharp
public enum CoordinateMode
{
    AbsoluteScreen,
    CloudDesktopRegion
}
```

`ClickProfile` 新增：

```csharp
public CoordinateMode CoordinateMode { get; set; }
public CloudDesktopRegion? CloudDesktopRegion { get; set; }
public ScreenStabilitySettings ScreenStability { get; set; } = new();
```

`CloudDesktopRegion` 保存本机屏幕上的云桌面内容区域：

```csharp
public sealed class CloudDesktopRegion
{
    public int X { get; set; }
    public int Y { get; set; }
    public int Width { get; set; }
    public int Height { get; set; }
    public string MonitorDeviceName { get; set; } = string.Empty;
    public uint CapturedDpi { get; set; } = 96;
}
```

`ClickPoint` 保留现有 `X/Y` 绝对坐标，并新增可空的相对坐标：

```csharp
public double? RelativeX { get; set; }
public double? RelativeY { get; set; }
```

相对坐标范围为 `0.0` 到 `1.0`。保留 `X/Y` 用于旧方案兼容、界面展示和云桌面区域失效时的诊断。

### 4.3 画面稳定参数

```csharp
public sealed class ScreenStabilitySettings
{
    public bool Enabled { get; set; }
    public int SampleIntervalMs { get; set; } = 250;
    public int StableDurationMs { get; set; } = 750;
    public int TimeoutMs { get; set; } = 15000;
    public double ChangeTolerancePercent { get; set; } = 2.0;
}
```

界面第一版只暴露启用开关和超时时间。其余参数使用上述安全默认值，避免增加零基础用户的配置负担。

## 5. 云桌面区域标定

### 5.1 操作流程

1. 用户打开“云桌面增强”开关。
2. 点击“标定区域”。
3. 将鼠标放到云桌面内容区域左上角，按采点快捷键。
4. 将鼠标放到云桌面内容区域右下角，按采点快捷键。
5. 程序校验宽高均不少于 `100` 像素，保存区域并在界面显示 `宽 x 高`。
6. 后续采点时同时保存绝对坐标和相对坐标。

标定期间不新增普通点位。标定完成或取消后恢复普通采点状态。

### 5.2 重新标定

用户移动浏览器、改变云桌面尺寸或切换全屏后，只需要重新标定区域。程序根据旧区域中的相对坐标重新计算所有云桌面点位的当前绝对位置。

旧的绝对坐标方案可通过“转换为云桌面方案”完成转换：先标定区域，再将位于区域内的点换算为相对坐标。区域外点位不转换，并提示具体序号。

### 5.3 坐标换算

采点：

```text
RelativeX = (PointX - RegionX) / RegionWidth
RelativeY = (PointY - RegionY) / RegionHeight
```

执行：

```text
TargetX = RegionX + round(RelativeX * RegionWidth)
TargetY = RegionY + round(RelativeY * RegionHeight)
```

执行前校验所有启用点的相对坐标在 `0.0..1.0` 范围内。

## 6. 鼠标输入可靠性

现有 `SetCursorPos` 后分别发送按下和抬起事件的方式，调整为：

1. 将目标像素坐标换算为 Windows 虚拟屏幕 `0..65535` 绝对坐标。
2. 使用带 `MOUSEEVENTF_MOVE | MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` 的 `SendInput` 移动鼠标。
3. 等待 `40ms` 后调用 `GetCursorPos` 验证落点。
4. 误差超过 `2px` 时最多重试两次。
5. 三次仍无法到达目标时停止当前执行并显示目标坐标、实际坐标和建议：
   - 退出云桌面指针锁定；
   - 保持浏览器窗口可见；
   - 重新标定云桌面区域；
   - 必要时在云桌面内部运行工具。

点击事件继续使用 `SendInput`，并在异常和取消路径中确保左键释放。

## 7. 画面稳定等待

### 7.1 检测方式

云桌面模式且“等待画面稳定”开启时，每个点完成固定的“点后等待”后：

1. 截取云桌面区域。
2. 将截图缩小到最多 `160 x 90` 并转为灰度采样。
3. 每 `250ms` 与上一帧比较平均像素差。
4. 变化比例连续低于 `2%` 达到 `750ms`，判定画面稳定。
5. 最长等待 `15s`，用户可在界面修改为 `3..60s`。

缩小和容差用于忽略鼠标闪烁、时钟、小范围动画等轻微变化。

### 7.2 超时处理

稳定等待超时后不得显示“全部循环已完成”，也不得直接点击下一点。

执行引擎暂停并报告：

```text
点位 3 后画面在 15 秒内未稳定。
请检查页面，按开始/继续快捷键强制继续，或按停止快捷键结束。
```

用户继续后从下一个点执行；用户停止则返回“用户停止”，并保留已执行数量。

## 8. 执行计划与结果

### 8.1 启动前确认

点击开始后，在倒计时前显示执行计划：

- 表格总行数。
- 启用点位数。
- 未启用点位数。
- 总循环次数。
- 预计总点击次数。
- 坐标模式。
- 云桌面区域尺寸。
- 画面稳定等待是否开启。

当总行数大于启用点位数时，以醒目文字提示“有 N 个点位未启用”。启用点为 `0` 时禁止开始。

### 8.2 执行进度

状态栏继续显示循环、点位和点击次数，并增加：

- 当前点位序号对应原表格行号。
- 已完成点位数。
- 画面稳定等待状态。
- 当前暂停原因。

### 8.3 完成结果

执行引擎返回带结束原因的 `ExecutionResult`：

```csharp
public enum ExecutionOutcome
{
    Completed,
    Stopped,
    Failed
}

public sealed record ExecutionResult(
    ExecutionOutcome Outcome,
    int EnabledPointCount,
    long PlannedPointExecutionCount,
    long PlannedClickCount,
    long CompletedPointExecutionCount,
    long CompletedClickCount,
    int? LastCompletedSourcePointIndex,
    string? Message,
    TimeSpan Elapsed);
```

正常完成后状态栏显示：

```text
执行完成：启用 8 个点，完成 16 个点次、24 次点击，用时 32.4 秒。
```

用户停止或发生错误时显示已经完成的点次和点击次数，不再只显示笼统的“执行已停止”。

只有同时满足以下条件时才允许显示“全部循环已完成”：

- `Outcome == Completed`。
- 已完成点次等于计划点次。
- 已完成点击次数等于计划点击次数。

任何数量不一致都按失败处理，并显示计划数、完成数和最后完成的原表格行号。

### 8.4 多步骤流程可靠性

复杂流程按以下规则执行：

1. 开始时一次性生成不可变执行计划，保留每个启用点对应的原表格行号，不允许静默截断。
2. 执行计划按“循环 -> 点位顺序 -> 单点点击次数”展开，使用 `long` 计算总点次和总点击次数。
3. 每完成一个点位立即更新完成计数和最后完成行号。
4. 采点模式结束时显示“本次新增 N 个点，当前共 M 个点”，避免用户误以为后续点位已经记录。
5. 执行前如果表格有未启用点，必须逐项列出未启用行号，并要求用户确认。
6. 稳定等待超时、鼠标落点失败、用户停止或其他异常时保存内存检查点。检查点精确记录下一次要执行的循环序号、点位序号和单点点击序号；单点执行到一半时继续剩余点击，不重复已经完成的点击。
7. 非正常结束后，开始按钮变为“从第 N 步继续”，用户也可以选择“重新开始”。
8. 断点继续使用原执行计划中尚未完成的点位，不重复已经完成的点位；重新开始则重新读取当前表格。
9. 每次运行写入 `%LocalAppData%\OrderedClicker\logs` 下的 JSON 执行记录，至少包含计划点数、启用点数、循环数、计划点击数、完成点击数、最后完成行号、结束原因和错误信息。

执行引擎自动化测试必须覆盖至少 `500` 个有序点位、`3` 次循环，验证共 `1500` 个点次全部按顺序执行，不允许只用两个点位的简单用例代表复杂流程。

## 9. 快捷键简化

设置页增加两个预设：

- 简洁模式：`F6` 采点、`F7` 开始/暂停、`F8` 停止。
- 兼容模式：`Ctrl+Alt+F8`、`Ctrl+Alt+F9`、`Ctrl+Alt+F10`。

兼容规则：

- 新安装默认使用简洁模式。
- 从 `v1.2.0` 升级时，如果用户仍使用旧版默认组合，则首次启动自动迁移为简洁模式。
- 用户已经自定义过快捷键时必须保留原配置，不自动覆盖。
- 简洁模式被系统或其他软件占用时，保留原快捷键并提示用户切换兼容模式或自定义。
- 用户可一键切换简洁模式或兼容模式。
- 无修饰键时，仅允许 `F6..F12`。
- 保存时继续检查重复组合和系统占用。
- 简洁模式注册失败时，提示切换兼容模式，不静默降级。

## 10. 保存与另存为

主界面增加“另存为”按钮，并记录当前方案路径。

- `保存`：
  - 已加载或另存过方案时，覆盖当前路径。
  - 新方案没有当前路径时，按方案名称保存到默认方案目录。
- `另存为`：
  - 打开 `SaveFileDialog`。
  - 默认扩展名为 `.json`。
  - 用户可选择任意有权限的目录。
  - 保存成功后将新路径设为当前方案路径。
- `加载`：
  - 加载成功后记录被加载文件路径。
- 状态栏显示实际保存路径。

另存为不自动修改方案名称，避免文件名变化意外改变界面内的业务名称。

“保存”“另存为”“加载”属于主界面固定功能，不得因布局调整、主题修改或云桌面模式关闭而隐藏。UI 冒烟测试必须同时检查三个按钮可见、可用且名称正确。

## 11. 界面设计

不重做主界面结构，仅在现有布局上增加一个紧凑的“云桌面增强”工具条：

- 云桌面增强开关。
- “标定区域”按钮。
- 区域状态，例如 `已标定 1420 x 760`。
- “等待画面稳定”开关。
- 稳定等待超时输入框。

方案操作区调整为：

```text
保存 | 另存为 | 加载
```

设置窗口增加：

```text
简洁模式 | 兼容模式 | 自定义
```

所有运行配置在执行期间禁用；停止按钮和开始/继续快捷键保持可用。

## 12. 组件边界

新增或调整以下职责：

- `CloudDesktopCoordinateService`
  - 标定区域校验。
  - 绝对坐标与相对坐标互转。
  - 旧点位批量转换。
- `AbsoluteMouseInputService`
  - 虚拟屏幕坐标标准化。
  - 绝对移动、落点验证和重试。
- `ScreenStabilityDetector`
  - 截屏采样、帧差比较和稳定超时。
- `ExecutionPlanService`
  - 生成执行前汇总。
  - 计算预计点击次数并防止整数溢出。
- `ExecutionCheckpointService`
  - 记录原执行计划、下一个循环/点位/点击位置和已完成计数。
  - 支持当前程序会话内从中断点继续。
- `ExecutionLogService`
  - 将每次执行计划和结果原子写入本地 JSON 日志。
- `ClickExecutionEngine`
  - 使用解析后的执行点快照。
  - 记录执行结果。
  - 在稳定超时时进入可恢复暂停。
- `ProfileService`
  - 支持指定路径保存。
  - 保持原子写入。
- `MainForm`
  - 只负责 UI 状态、对话框、模式切换和服务协调。

## 13. 错误处理

- 区域未标定：禁止以云桌面模式开始。
- 区域宽高不足：拒绝保存标定结果。
- 点位在区域外：采点时拒绝并显示目标坐标与区域范围。
- 重新标定后点位换算越界：列出具体点位序号并禁止开始。
- 鼠标无法到达目标：停止执行并保留完成明细。
- 截图失败：暂停执行，允许用户强制继续或停止。
- 画面稳定超时：暂停，不自动跳过。
- 保存失败：保留原文件，不更新当前方案路径。
- 快捷键冲突：保留原快捷键。

## 14. 测试策略

### 14.1 单元测试

- 区域相对坐标往返换算。
- 负坐标显示器的虚拟屏幕绝对坐标标准化。
- 区域边界、最小尺寸和点位越界校验。
- 旧版本方案按绝对坐标加载。
- 版本 3 云桌面方案保存和恢复。
- 简洁模式允许单独 `F6..F12`，拒绝其他无修饰键。
- 快捷键预设不产生重复组合。
- 旧版默认快捷键迁移为简洁模式，自定义快捷键保持不变。
- 保存与另存为路径行为。
- 执行计划的启用点数和总点击次数。
- 执行结果的完成计数。
- `500` 个点位、`3` 次循环的顺序与完整性。
- 计划数量与完成数量不一致时不得返回正常完成。
- 中断后从下一个未完成点位继续，不重复已完成点位。
- 执行日志包含计划数、完成数、最后行号和结束原因。
- 稳定检测成功、超时暂停、继续和取消。

### 14.2 UI 冒烟测试

- 主界面始终存在“保存”“另存为”“加载”三个方案按钮。
- 标定状态按左上角、右下角顺序变化。
- 执行前确认准确显示总行数和启用点数。
- 采点结束时显示本次新增数和当前总数。
- 非正常结束后显示“从第 N 步继续”和“重新开始”。
- 设置窗口可切换简洁/兼容快捷键预设。
- 执行期间配置控件禁用。

### 14.3 人工验证

在本机浏览器云桌面环境执行：

1. 窗口化标定并采集至少 6 个点。
2. 验证全部点位按顺序执行。
3. 移动浏览器后重新标定区域，确认不需要逐点重采。
4. 模拟页面慢加载，确认稳定等待生效。
5. 制造持续变化页面，确认超时后暂停。
6. 使用至少 20 个点位验证完整执行、进度计数和完成摘要。
7. 在第 10 个点位停止，确认可从第 11 个点位继续。
8. 分别验证简洁模式和兼容模式快捷键。
9. 验证保存、另存为、加载和旧方案兼容。

## 15. 兼容性与迁移

- 旧 `Version 1/2` JSON 文件可直接加载。
- 旧方案默认保持绝对坐标模式。
- 旧主题和快捷键设置保持不变。
- 新增字段缺失时使用默认值。
- 不删除或重命名用户现有方案。
- 产品目录中的旧版本安装包由构建脚本清理，视频文件沿用现有版本。

## 16. 风险

1. 云桌面启用浏览器指针锁定时，本机绝对鼠标输入仍可能被转换为相对输入。程序只能检测本机光标落点，无法读取远端系统真实光标位置。
2. 持续动画、视频或频繁刷新的页面可能无法达到稳定条件，需要用户关闭稳定等待或在超时后强制继续。
3. 相对坐标只能适应云桌面区域整体移动或等比例布局变化，无法解决公司系统内部控件重新排版。
4. `SendInput` 无法向权限级别高于本程序的窗口注入输入。出现此情况时需要以相同或更高权限运行连点器。
5. 截屏稳定检测会产生少量 CPU 开销，因此采用低分辨率采样并仅在点后等待阶段运行。

## 17. 验收标准

- 用户可标定云桌面区域，并采集至少 10 个相对点位。
- 重新标定区域后，原点位无需逐个重采即可重新换算。
- 执行前明确显示总行数和启用点数；仅启用两个点时必须醒目提示。
- `500` 个点位执行 `3` 次循环时，必须完成全部 `1500` 个点次且顺序一致。
- 正常完成状态必须同时通过计划点次和实际点次一致性校验。
- 长流程停止或失败后可以从下一个未完成点位继续。
- 每次执行均生成包含计划、完成和结束原因的本地记录。
- 稳定等待超时后停在当前流程并等待用户决定，不得显示正常完成。
- 用户可一键使用 `F6/F7/F8`，也可切回兼容快捷键。
- 新安装默认显示并注册 `F6/F7/F8`；升级用户的自定义快捷键不得被覆盖。
- 用户可使用“另存为”选择 JSON 保存路径。
- 旧方案、旧主题和旧快捷键配置可以继续使用。
- 自动化测试、安装器契约测试和指导文件校验全部通过。
