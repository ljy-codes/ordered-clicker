# 有序连点器 Windows 安装版设计

## 1. 背景与目标

当前项目已经能够发布为 Windows x64 自包含单文件程序，并通过 GitHub Releases 提供便携版和使用说明。下一版本需要在不改变现有连点器核心功能的前提下，增加面向零基础普通用户的标准 Windows 安装程序。

本次目标：

- 提供双击即可安装的 `Setup.exe`。
- 默认按当前用户安装，无需管理员权限。
- 创建开始菜单入口，并允许用户选择是否创建桌面快捷方式。
- 支持从 Windows“已安装的应用”中卸载。
- 后续版本可直接覆盖安装，同时保留用户方案与主题设置。
- 继续提供便携版，满足免安装使用场景。
- 将安装版作为新版本发布到 GitHub Releases。

本次不包含：

- 自动更新或后台更新服务。
- 企业级 MSI 部署、组策略分发或集中管理。
- 购买和配置代码签名证书。
- 修改连点、采点、主题、方案保存等现有业务功能。

## 2. 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 安装包形式 | 标准单文件 `Setup.exe` |
| 安装范围 | 当前用户 |
| 管理员权限 | 安装过程不要求管理员权限 |
| 更新方式 | 用户下载新安装包后覆盖安装 |
| 自动更新 | 不实现 |
| 代码签名 | 当前版本不签名 |
| 安装框架 | Inno Setup 7 |
| 目标架构 | Windows x64 |
| 计划版本 | `v1.0.1` |

## 3. 用户体验

### 3.1 安装流程

安装向导采用简体中文，流程保持简洁：

1. 欢迎页。
2. 安装位置确认。
3. 附加任务选择。
4. 安装确认与文件复制。
5. 完成页。

附加任务：

- 创建桌面快捷方式，默认选中，允许取消。
- 安装完成后运行“有序连点器”，默认选中。

安装器应使用应用图标，并尽量跟随 Windows 深浅色外观。安装页面不加入与安装无关的介绍、广告或网络请求。

### 3.2 默认安装位置

安装目录：

```text
%LocalAppData%\Programs\OrderedClicker
```

该位置属于当前用户，不写入 `Program Files`，因此正常情况下不会触发 UAC。

开始菜单目录：

```text
有序连点器
```

开始菜单至少包含：

- 有序连点器
- 卸载有序连点器

### 3.3 卸载行为

卸载程序删除：

- 安装目录中的应用程序文件。
- 开始菜单快捷方式。
- 安装器创建的桌面快捷方式。
- Windows“已安装的应用”中的卸载记录。

卸载程序默认保留用户数据，避免误删方案：

```text
%LocalAppData%\OrderedClicker\profiles
%LocalAppData%\OrderedClicker\settings.json
```

如将来需要“彻底清除数据”，应单独设计确认步骤，不在本版本中隐式删除。

## 4. 安装器技术设计

### 4.1 安装框架

采用 Inno Setup 7，原因如下：

- 可生成单个 Windows 安装程序。
- 支持当前用户安装和标准卸载入口。
- 支持开始菜单、桌面快捷方式和安装完成后启动。
- 可通过稳定 `AppId` 识别同一产品，支持覆盖升级。
- 脚本易于纳入仓库和自动构建。
- 相较 MSI/MSIX，当前项目无需额外签名和企业部署复杂度。

### 4.2 稳定产品标识

安装脚本使用固定 `AppId`，首次生成后不再修改。后续版本沿用该标识，以确保：

- 新版本能够识别旧版本安装位置。
- Windows 中只显示一个产品卸载项。
- 覆盖安装不会形成多个重复应用。

`AppId` 使用项目专属 GUID，并在安装脚本中以常量形式保存。

### 4.3 权限与运行级别

安装脚本配置：

```text
PrivilegesRequired=lowest
```

应用程序清单继续使用普通用户级别：

```text
asInvoker
```

连点器操作普通权限应用时无需管理员权限。如果目标程序本身以管理员身份运行，Windows 完整性级别会阻止普通权限连点器向其发送输入；用户需要手动右键以管理员身份运行连点器。安装器不默认提升应用权限，避免每次启动出现 UAC。

### 4.4 文件布局

仓库增加：

```text
installer/
├─ OrderedClicker.iss
└─ assets/
   └─ ordered-clicker.ico

scripts/
└─ build-installer.ps1
```

职责：

- `installer/OrderedClicker.iss`：定义产品信息、安装目录、快捷方式、卸载入口和安装完成动作。
- `installer/assets/ordered-clicker.ico`：安装器与应用快捷方式图标。
- `scripts/build-installer.ps1`：执行测试、发布应用、调用 Inno Setup 编译器、计算校验值并整理产物。

现有 `scripts/publish.ps1` 继续作为应用发布入口，避免重复维护 .NET 发布参数。

### 4.5 应用发布

应用仍采用现有 .NET 自包含单文件发布方式：

```text
RuntimeIdentifier=win-x64
SelfContained=true
PublishSingleFile=true
```

安装器将发布目录中的 `OrderedClicker.exe` 复制到安装目录。用户机器无需预装 .NET Runtime。

项目文件增加应用图标配置，使以下位置显示统一图标：

- 应用程序窗口和任务栏。
- 可执行文件。
- 开始菜单快捷方式。
- 桌面快捷方式。
- 安装程序。

## 5. 版本与产物

### 5.1 版本策略

不修改已经发布的 `v1.0.0`，安装版作为新版本：

```text
v1.0.1
```

安装程序文件名：

```text
ordered-clicker-setup-v1.0.1.exe
```

便携版建议保持：

```text
ordered-clicker-portable-v1.0.1.zip
```

### 5.2 发布目录

本地最终交付目录继续使用：

```text
D:\专用工具\连电器产品
```

至少保存：

- `ordered-clicker-setup-v1.0.1.exe`
- `ordered-clicker-portable-v1.0.1.zip`
- 使用说明 PDF
- 使用说明 HTML
- 视频演示
- `SHA256SUMS.txt`

安装包和便携版随后上传到 GitHub Release `v1.0.1`，说明安装版与便携版的区别。

## 6. 构建流程

`scripts/build-installer.ps1` 按以下顺序执行：

1. 检查 Inno Setup 编译器是否可用。
2. 运行现有自动化测试。
3. 调用 `scripts/publish.ps1` 生成 Windows x64 自包含程序。
4. 清理本次安装包的临时输出目录，不删除用户数据或仓库外文件。
5. 调用 Inno Setup 编译 `OrderedClicker.iss`。
6. 将安装包重命名为带版本号的标准文件名。
7. 计算安装包和便携包的 SHA-256。
8. 将发布文件整理到产品目录。

脚本任何一步失败时立即停止，并返回非零退出码，避免将不完整产物误认为正式版本。

## 7. 验证方案

### 7.1 自动化验证

- 现有单元测试全部通过。
- Release 配置编译成功。
- 自包含发布成功。
- Inno Setup 编译成功。
- 安装包和便携包生成 SHA-256。

### 7.2 安装冒烟测试

在普通用户环境验证：

1. 双击安装包，不要求管理员权限。
2. 默认安装路径正确。
3. 开始菜单快捷方式可启动应用。
4. 选择桌面快捷方式后可正常启动。
5. 应用窗口、任务栏和快捷方式图标正确。
6. 采点、排序、单点点击次数、总循环次数、启动和停止正常。
7. 高 DPI 或系统缩放为 125%、150% 时界面和坐标行为正常。
8. 主题设置、方案保存和加载正常。
9. 安装新版本覆盖旧版本后，用户方案和主题设置仍存在。
10. 从 Windows“已安装的应用”卸载成功。
11. 卸载后用户方案和主题设置仍保留。

### 7.3 兼容性

目标环境：

- Windows 10 x64。
- Windows 11 x64。
- 常见系统缩放比例：100%、125%、150%、175%。

不支持：

- Windows 32 位系统。
- macOS、Linux。
- Windows ARM64 原生安装包。

## 8. 兼容性与影响范围

本次修改不改变现有配置目录和配置格式，因此：

- 便携版和安装版可读取同一当前用户配置。
- 现有方案文件无需迁移。
- 已有热键和点击逻辑保持不变。
- GitHub 上的 `v1.0.0` 继续可用。

影响范围限于：

- 应用图标元数据。
- 安装器脚本。
- 构建与发布脚本。
- README 中的安装说明。
- 发布产物和 GitHub Release。

## 9. 风险与处理

### 9.1 Windows SmartScreen

由于当前没有代码签名证书，安装包可能显示“未知发布者”，并可能被 Microsoft Defender SmartScreen 提示。处理方式：

- 在 README、PDF 和 HTML 指导中明确说明官方仓库与校验方式。
- Release 同时提供 SHA-256。
- 不绕过或关闭 Windows 安全机制。
- 后续获取代码签名证书后，再为应用与安装器签名。

### 9.2 高权限目标程序

普通权限连点器无法可靠控制管理员权限目标程序。处理方式：

- 应用保持普通权限启动。
- 使用说明明确：仅在目标程序为管理员权限时，手动以管理员身份运行连点器。

### 9.3 安装器工具依赖

构建安装包需要 Inno Setup 编译器。处理方式：

- 构建脚本先检测常见安装路径。
- 未找到时输出清晰的安装提示并停止。
- 安装器编译工具不打包进仓库。

### 9.4 覆盖升级

如果后续误改 `AppId` 或安装目录规则，可能产生重复安装项。处理方式：

- 将 `AppId` 固定在脚本中。
- 把覆盖安装和卸载保留数据列为每次发版必测项。

## 10. 验收标准

满足以下条件即可验收：

- 生成可双击运行的单文件安装程序。
- 普通用户安装时不触发管理员权限请求。
- 安装、启动、覆盖升级和卸载流程完整。
- 开始菜单和可选桌面快捷方式正常。
- 用户配置在覆盖升级与卸载后保留。
- Windows 10/11 x64 和常见屏幕缩放下核心功能可用。
- 现有测试全部通过，无核心功能回归。
- 产品目录包含安装版、便携版、PDF、HTML、视频和校验文件。
- GitHub Release `v1.0.1` 包含安装版并注明未签名提示。
