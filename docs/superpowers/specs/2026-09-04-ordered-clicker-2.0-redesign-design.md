# 有序连点器 2.0 全面重做设计

## 1. 目标

将现有单页 WinForms 连点器重做为面向普通本地连点和云桌面长流程的分步工作台，优先解决以下用户风险：

- 云桌面重新校准后点位错位。
- 停止后界面配置与待继续执行计划不一致。
- 断点继续跳过未完成的等待或画面稳定检查。
- 关闭、导入和首次保存导致方案丢失或静默覆盖。
- 停止热键不可用时仍可启动，缺少可靠紧急停止手段。
- 暂停状态与实际后台计时不一致。
- 采点、校准、长等待和日志反馈不可见。
- 高 DPI、小屏幕、4K 稳定检测及首次安装体验不足。

产品版本升级为 `2.0.0`。方案格式升级为不向后兼容的 `v4`，旧 JSON 方案只能通过一次性迁移流程进入新格式。

## 2. 设计原则

1. 安全优先：没有可靠停止通道时不允许执行。
2. 所见即所得：界面显示的配置必须与即将执行的不可变计划一致。
3. 不丢数据：编辑过程实时写入恢复草稿，任何替换当前内容的操作都先保存草稿。
4. 保守恢复：断点继续不重复已完成点击，但必须重新完成未通过的等待和稳定检测屏障。
5. 渐进复杂度：普通本地连点与云桌面长流程同等可达，高级功能仅在对应模式中出现。
6. 可诊断：用户能看到当前阶段、剩余时间、安全状态和本次日志。

## 3. 信息架构

主窗口采用三栏分步工作台。

### 3.1 左侧步骤导航

固定包含五个步骤：

1. 选择模式。
2. 方案配置。
3. 采集点位。
4. 执行检查。
5. 运行与日志。

步骤不是一次性向导。用户可以返回任何已完成步骤修改；修改执行相关数据后，执行检查立即失效，旧计划和旧断点同时废弃。

### 3.2 中央工作区

中央区域只展示当前步骤的核心控件：

- 选择模式：本地模式、云桌面模式及差异说明。
- 方案配置：名称、循环、轮间等待、画面稳定策略。
- 采集点位：点位表格、采点控制、顺序、单点时间和撤销操作。
- 执行检查：问题列表、安全通道、预计耗时和试运行入口。
- 运行与日志：实时阶段、进度、暂停、停止、断点和日志。

### 3.3 右侧状态栏

持续显示：

- 草稿保存状态。
- 当前方案及绑定路径。
- 停止热键注册状态。
- 安全角状态。
- 云桌面校准状态。
- 点位数、计划点击数和预计耗时。

设置、帮助、数据目录和诊断入口放入标题栏菜单，不再占用核心工作区。

## 4. 方案格式与文件语义

### 4.1 v4 方案格式

新方案扩展名为 `.oclick`，内部为 UTF-8 JSON。顶层至少包含：

- `formatVersion`: 固定为 `4`。
- `profileId`: 全局唯一标识。
- `name`: 用户可见名称。
- `mode`: `local` 或 `cloudDesktop`。
- `createdAtUtc`、`updatedAtUtc`。
- `loopSettings`。
- `screenStabilitySettings`。
- `cloudDesktopRegion`。
- `points`。
- `safetySettings`。

显示名称不再决定文件名和身份。文件重命名不会改变 `profileId`，另存为会生成新的 `profileId`。

### 4.2 打开、保存和另存为

- “打开方案”可打开任意目录中的 `.oclick` 并绑定该源文件。
- “保存”原子写回当前绑定文件。
- “另存为”创建新身份并绑定新文件。
- 覆盖已有文件前必须确认，并在相同目录生成最近一次 `.bak` 备份。
- 最近打开列表记录路径；文件不存在时显示可移除的失效项。
- 同名显示名称允许存在，但界面同时显示文件路径或目录，避免混淆。

### 4.3 自动草稿

编辑变化通过防抖机制写入活动草稿：

```text
%LocalAppData%\OrderedClicker\drafts\active-draft.oclick
```

草稿写入使用同目录临时文件和原子替换。草稿元数据记录来源方案路径、来源方案更新时间和最后编辑时间。

- 异常退出或未正式保存时，下次启动提供“恢复草稿”和“放弃草稿”。
- 正常关闭不强制保存正式方案，但明确提示正式方案未保存、恢复草稿已保留。
- 打开、导入迁移或切换模式前先刷新活动草稿。
- 恢复成功后不会自动覆盖原方案，用户仍需主动保存。

### 4.4 旧方案迁移

旧 `.json` 文件不能直接作为当前方案打开，只能通过“迁移旧方案”处理。

迁移读取旧名称、循环设置、点位、点击次数、点击间隔、点后等待、坐标模式和云桌面区域。迁移结果写入新的 `.oclick`，不修改来源文件。

迁移完成后显示：

- 成功转换字段。
- 使用默认值的字段。
- 缺少相对坐标或需要重新采集的点位。
- 新方案保存路径。

旧方案迁移不提供回写旧格式能力。

## 5. 执行计划和失效规则

执行检查成功后生成不可变 `ExecutionPlan` 和配置指纹。指纹覆盖：

- 模式和云桌面区域。
- 点位启用状态、顺序、坐标、点击次数和时间。
- 循环次数和轮间等待。
- 画面稳定设置。
- 安全角设置。

任何覆盖字段变化都会：

1. 清除当前执行计划。
2. 清除断点。
3. 将执行检查标记为待重新检查。
4. 禁止直接继续旧任务。

切换方案、迁移方案、切换模式和重新校准同样执行该失效流程。

## 6. 安全断点模型

断点除循环、点位和点击序号外，还记录阶段：

- `BeforeClick`
- `ClickInterval`
- `AfterPointDelay`
- `ScreenStability`
- `LoopDelay`
- `Committed`

每次点击成功后立即记录已完成点击计数，但只有点后等待、稳定检测和必要轮间等待全部完成后，才提交进入下一安全边界。

停止或异常发生后：

- 已完成点击不重复。
- 未完成的点击间隔重新执行完整间隔。
- 未完成的点后等待重新执行完整等待。
- 未通过的画面稳定检查重新开始检测。
- 未完成的轮间等待重新执行完整等待。

这是保守恢复语义，不保存等待阶段已经消耗的毫秒数。

## 7. 暂停与关闭

所有可等待阶段统一通过可暂停延时服务执行。暂停后：

- 延时停止消耗。
- 画面稳定检测停止采样。
- 执行线程确认暂停后，界面才显示“已暂停”。
- 恢复后继续剩余延时，不重置正常暂停前已消耗的时间。

关闭程序时：

1. 若正在执行，提示用户停止并退出或取消关闭。
2. 用户确认后发送取消信号。
3. 等待执行引擎释放鼠标按键、保存断点和写入日志。
4. 超时仍未退出时显示错误，不直接终止进程。
5. 刷新活动草稿后关闭。

## 8. 双重紧急停止

执行必须同时具备两条安全通道：

1. 已成功注册的全局停止热键。
2. 已启用且验证有效的屏幕安全角。

用户可以在执行检查中选择某块显示器的四个角之一。安全角区域大小固定并在界面可视化。任何启用点位与安全角重叠时，执行检查失败，用户必须更换安全角或移动点位。

执行期间独立安全监控检测光标进入安全角并取消任务。停止热键或安全角监控初始化失败时禁止启动。

采点热键失败时仍提供“记录当前位置”按钮；界面不得再笼统提示所有按钮都能替代全局热键。

## 9. 采点与云桌面校准

### 9.1 采点 HUD

采点期间显示置顶小型 HUD：

- 当前模式。
- 已采点数量。
- 采点快捷键。
- “记录当前位置”。
- “结束采点”。

每次采点提供短暂视觉反馈和可关闭提示音。新点与已有点距离低于阈值时提示可能重复，用户可以保留或取消。

删除点位进入撤销记录。清空全部点位仍需二次确认。空表格显示明确的采点入口和快捷键。

### 9.2 云桌面校准

校准使用透明覆盖层记录矩形区域并显示边框、宽高和显示器信息。记录、取消和重新开始使用独立操作。

重新校准时：

- 已有合法 `RelativeX`、`RelativeY` 保持不变。
- 只更新新的云桌面区域。
- 绝对预览坐标根据新区域重新计算。
- 缺少相对坐标的点位不会静默转换，统一列入待处理列表。

校准完成后立即显示有效、缺失和越界点位数量。

## 10. 画面稳定检测

屏幕采样直接生成最大 `160x90` 的 RGB 样本，并复用采样缓冲区，不创建完整区域位图后再缩放。

差异计算同时考虑亮度和颜色通道，避免仅颜色变化被误判为稳定。检测过程支持暂停和取消，并上报：

- 当前检测时长。
- 最大等待时间。
- 最近差异值。
- 当前是否已进入稳定持续时间。

检测超时后保持暂停状态，由用户选择继续检测、跳过一次或停止。跳过一次必须写入执行日志。

## 11. 执行检查与预计耗时

执行检查集中展示并阻止以下问题：

- 停止热键未注册。
- 安全角不可用或与点位重叠。
- 云桌面区域未校准。
- 点位缺少相对坐标或越界。
- 点位数、循环数或时间参数无效。
- 当前计划与界面配置指纹不一致。

预计耗时分为：

- 基础预计耗时：点击间隔、点后等待和轮间等待之和。
- 稳定检测附加范围：最少为零，最多按每次检测超时累计。
- 计划点击数和计划点次。

提供单轮试运行入口。长任务未完成单轮试运行时显示警告，但允许用户明确确认后执行。

## 12. 运行状态与日志

运行界面持续显示：

- 当前循环、点位和点击序号。
- 当前阶段。
- 当前阶段剩余时间或稳定检测进度。
- 已完成点击数和计划点击数。
- 暂停、继续和停止操作。

执行结束后提供：

- 打开本次日志。
- 打开日志目录。
- 复制诊断摘要。
- 从安全断点继续。
- 清除断点并重新开始。

日志写入失败必须进入最终结果提示，不能被“全部完成”状态覆盖。

应用级诊断日志覆盖启动、设置、热键、方案、迁移、校准和执行异常，包含版本、时间、操作、异常类型、消息和堆栈。

## 13. 设置和输入体验

设置中心分为：

- 快捷键。
- 安全。
- 界面。
- 数据目录。
- 诊断。

“简洁模式”和“兼容模式”改名为“单键快捷键”和“组合快捷键”，界面直接展示具体按键。冲突在输入框旁即时显示。

模态窗口打开期间暂停处理采点和开始热键；停止热键只在确有运行任务时生效。

术语调整：

- “点击间隔”改为“同点连击间隔”。
- “点后等待”改为“步骤完成后等待”。

无效输入标记对应控件或表格单元格，并自动定位。设置和帮助窗口支持缩放、最大化及高 DPI 滚动。

## 14. 安装版、免安装版与发布

安装版继续将数据写入：

```text
%LocalAppData%\OrderedClicker
```

免安装交付文件统一命名：

```text
有序连点器-免安装.exe
```

免安装程序根据进程文件名进入 portable 模式，将数据写入程序旁：

```text
OrderedClickerData
```

目录不可写时明确报错并提示移动程序，不静默回退到安装版目录。

发布目录生成：

- `ordered-clicker-setup-v2.0.0.exe`
- `有序连点器-免安装.exe`
- `有序连点器-使用说明.pdf`
- `有序连点器-使用说明.html`
- `SHA256SUMS.txt`

构建脚本支持 Authenticode 证书路径、证书密码来源和时间戳地址。开发构建允许不签名，正式发布模式缺少签名或签名验证失败时必须失败。

README、HTML、PDF、视频字幕和旁白稿统一使用 `2.0.0` 文件名、术语、热键和分步工作台流程。

## 15. 响应式与视觉规范

主窗口基于 DPI 自动缩放，三栏采用最小宽度和可折叠策略：

- 宽度不足时右侧状态栏折叠为可展开区域。
- 左侧步骤导航可收窄为图标和短标签。
- 中央工作区允许纵向滚动。
- 操作栏允许换行，不使用固定总宽度布局。
- 100%、150% 和 200% DPI 下核心按钮均可见。

按钮颜色仅用于主要操作、危险操作和状态，不再为每个普通按钮分配不同强调色。图标使用统一图标资源，不使用依赖系统字体的 Emoji。

## 16. 兼容性

- 不保证新 `.oclick` 由 1.x 版本读取。
- 1.x JSON 只能迁移，不能直接编辑或导出回旧格式。
- 鼠标点击、DPI 物理坐标和多显示器负坐标能力继续保留。
- 现有用户设置可读取基础主题和快捷键；读取后升级到新设置格式。
- 安装路径和 GitHub 仓库地址保持不变。

## 17. 测试与验收

自动化测试必须覆盖：

- 活动草稿原子保存、恢复和来源冲突。
- 同名方案、覆盖确认、备份和任意路径绑定。
- 旧 JSON 迁移成功、部分迁移和失败不覆盖。
- 云桌面平移、缩放、完全错开后重新校准不修改相对坐标。
- 配置变化使计划和断点失效。
- 点击、点击间隔、点后等待、稳定检测和轮间等待阶段的停止与继续。
- 暂停冻结剩余等待和稳定采样。
- 停止热键、安全角及重叠点位校验。
- 执行中关闭的有序取消。
- RGB 低分辨率采样和缓冲区复用。
- 日志失败不会被最终状态覆盖。
- 安装版和 portable 数据目录隔离。
- 设置损坏备份和用户提示。

UI 验收覆盖：

- 空状态、步骤导航、错误定位和撤销。
- 采点 HUD、校准覆盖层和运行状态窗。
- 100%、150%、200% DPI。
- 最小支持窗口尺寸和窄屏折叠。
- 浅色和深色主题。

发布验收包括：

- 完整测试通过。
- Release 构建无警告。
- 安装器构建和静默安装验证。
- 正式模式签名及时间戳验证。
- SHA-256 清单验证。
- 文档文件名、版本号、默认热键和按钮名称自动校验。

## 18. 非目标

- 不实现 OCR、图像识别定位或脚本语言。
- 不实现条件分支、变量和通用流程画布。
- 不支持 macOS、Linux 或移动平台。
- 不绕过管理员权限、反作弊或安全软件的输入限制。
- 不提供云同步和账号系统。
