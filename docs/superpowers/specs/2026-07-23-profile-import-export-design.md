# 方案文件导入导出设计

## 目标

让普通用户能够把当前连点方案保存成独立文件，用于备份、复制到其他电脑或分享给其他用户，并能安全导入已有方案文件。

## 用户操作

主界面提供四个明确操作：

- **保存**：覆盖当前已绑定的本机方案；没有绑定路径时保存到程序默认方案目录。
- **另存为**：选择新路径保存，并把该路径作为后续“保存”的目标。
- **导出方案**：选择任意路径生成分享文件，但不改变当前方案的保存路径。
- **导入方案**：读取外部文件，校验并显示摘要，确认后作为本机副本打开。

导入为副本意味着：

- 不绑定来源文件路径。
- 后续点击“保存”不会覆盖来源文件。
- 导入后清除旧执行计划和断点。
- 用户取消确认或文件校验失败时，当前界面保持不变。

## 文件格式

继续使用 UTF-8、带缩进的 JSON 文件，扩展名为 `.json`。不增加专用扩展名，保证已有 v1、v2、v3 方案继续可读。

文件保存完整 `ClickProfile`：

- 方案名称、总循环次数、轮间等待。
- 全局点击间隔和点后等待默认值。
- 点位顺序、启用状态、坐标、点击次数和时间参数。
- 显示器、DPI、云桌面区域和相对坐标。
- 画面稳定等待设置。

## 校验规则

导入阶段执行与运行环境无关的文件校验：

- 只接受版本 1 至 3，拒绝未来版本。
- 总循环、轮间等待和默认时间必须在程序支持范围内。
- 每个点的点击次数、点击间隔和点后等待必须合法。
- 云桌面模式必须包含有效区域和 0 至 1 的相对坐标。
- 允许空点位方案，便于导入模板。
- 不因显示器名称、分辨率或绝对坐标变化拒绝导入；运行前继续由现有校验和警告处理。

## 界面与反馈

- 原“加载”按钮替换为“导入方案”，新增“导出方案”按钮。
- 导入确认框显示方案名称、点位总数、启用点数和总循环次数。
- 导入、导出成功后状态栏显示完整文件路径。
- 导入失败使用受控错误提示，不泄露异常堆栈。
- 按钮提供工具提示，说明“导入为副本”和“导出不改变保存路径”。

## 代码边界

- `ProfileService`：负责 JSON 原子写入、读取和导入文件结构校验。
- `MainForm`：负责文件选择、导入确认、应用方案及当前路径语义。
- `ProfileServiceTests`：覆盖导出往返、未来版本拒绝、非法点位拒绝和损坏 JSON。
- `UiSmokeTests`：检查导入、导出、保存和另存为按钮均存在。

## 兼容性

- 不改变现有 JSON 字段名。
- v1、v2、v3 文件继续兼容。
- 保存和另存为行为保持不变。
- 导出文件可被 v1.3.1 及后续兼容版本导入。
