# 有序连点器 2.1 可靠性增强设计

## 目标

将有序连点器从 `2.0.0` 提升到 `2.1.0`，集中解决长时间、高频执行时的停止响应、异常退出恢复、多实例数据竞争、自动保存卡顿和交付自动化问题。现有 `.oclick` v4 方案格式、设置格式和默认快捷键保持兼容。

## 范围

本版本包含：

- 执行进度合并刷新，避免每次点击都向 UI 消息队列投递更新。
- 安全角后台监控，不依赖 WinForms 定时器。
- 运行中关闭窗口时先取消并等待执行任务退出。
- 执行断点持久化，程序异常退出后可恢复。
- 单实例运行，第二次启动时激活已有窗口。
- 延时记录任务防重入、可取消。
- 草稿保存使用 dirty 标记和防抖，减少重复序列化与同步写盘。
- 执行日志和诊断日志保留策略。
- 测试入口修正，保证自动化命令确实执行测试。
- `2.1.0` 版本、文档、交付产品和 GitHub Release 更新。

本版本不包含：

- `.oclick` 文件格式升级。
- 主界面重新布局。
- 云桌面坐标模型调整。
- 自动联网更新客户端。

## 方案选择

采用“局部协调器和服务”方案，而不是继续把生命周期逻辑堆入 `MainForm`，也不进行全量架构重写。

- `SingleInstanceCoordinator` 管理命名 Mutex 和激活事件。
- `ExecutionCheckpointService` 管理断点原子读写、隔离损坏文件和清理。
- `LatestExecutionProgress` 保存工作线程最新进度，UI 定时读取并显示。
- `SafetyCornerWatchdog` 在后台轮询安全角并直接触发取消。
- `LogRetentionService` 按时间、数量和总容量清理日志。

这些类均不依赖具体控件，便于控制台测试程序直接验证。

## 执行与停止

执行引擎仍在后台任务运行。引擎可以高频报告进度，但报告对象只覆盖内存中的最新值，不向 UI 逐条排队。UI 每 100ms 读取一次最新值；要求用户继续、停止、完成等状态变化立即触发一次 UI 刷新。

安全角改为独立后台任务，每 50ms 获取鼠标位置并调用现有 `SafetyCornerService`。触发后直接取消当前 `CancellationTokenSource`，再通过 `BeginInvoke` 更新界面。这样即使 UI 更新暂时拥堵，取消信号仍能送达执行引擎。

`MainForm` 保存当前执行任务。用户在执行中关闭窗口时：

1. 第一次关闭设置 `e.Cancel = true`。
2. 界面进入“正在安全停止”。
3. 取消执行并恢复暂停门。
4. 等待执行任务结束和鼠标按键释放。
5. 持久化最终断点和日志。
6. 设置允许关闭标记，再次调用 `Close()`。

## 持久化断点

断点文件位于应用数据目录的 `drafts/execution-checkpoint.json`，采用临时文件加原子替换。内容包括：

- 数据格式版本。
- 应用版本。
- 完整执行计划。
- 计划指纹。
- 当前 `ExecutionCheckpoint`。
- 保存时间。

执行期间最多每 500ms 合并保存一次，点位完成、暂停、停止、失败和窗口关闭时强制保存。完整完成或用户选择重新开始后删除断点。

启动时如果断点文件有效且计划指纹一致，询问用户恢复或丢弃。损坏文件移动为带时间戳的 `.broken.json`。异常掉电附近的最后少量外部点击无法实现事务级“恰好一次”，恢复提示中明确最后一步可能需要用户确认。

## 单实例

程序启动时获取按用户区分的命名 Mutex。首个实例同时启动命名事件监听任务；第二实例无法获取 Mutex 时设置激活事件并退出。首个实例收到事件后恢复最小化窗口、显示并置前。

草稿和设置临时文件同时改为 GUID 文件名，作为跨进程或异常残留情况下的第二层保护。

## 延时记录

延时记录由单个 `CancellationTokenSource` 管理。重复点击时不会新增并行任务，而是取消旧任务后重新开始两秒倒计时。结束采集、开始执行和关闭窗口时取消。倒计时期间按钮禁用并显示剩余时间。

## 草稿与日志

点位、循环、稳定性和相关配置发生变化时标记草稿 dirty。WinForms 防抖定时器只在 dirty 时创建一次快照并保存，不再每 800ms 序列化比较完整方案。保存成功后清除 dirty；失败时保留 dirty，等待下一次重试。

执行日志和诊断日志默认保留：

- 最近 30 天。
- 每类最多 1000 个文件。
- 每类总计不超过 100MB。

清理失败只写入诊断或忽略，不阻断程序启动和正常执行。

## 测试与发布

保留现有无第三方测试框架的控制台测试，增加明确的 `test.ps1` 入口，并在解决方案级 `dotnet test` 流程中调用真实测试程序，防止零测试成功。新增测试覆盖：

- 断点保存、加载、清理和损坏隔离。
- 最新进度覆盖和消费。
- 日志按时间、数量、容量清理。
- 单实例名称稳定性与激活协调器可释放。
- 延时任务协调逻辑。

GitHub Actions 在 Windows 上执行恢复、构建、真实测试和安装包构建。标签 `v2.1.0` 触发 Release，并上传安装包、便携包、说明文档和 `SHA256SUMS.txt`。签名证书不存在时生成未签名预发布产物；正式发布仍以本地签名流程或配置的仓库 Secret 为准。

## 兼容性与风险

- `.oclick` 保持 v4，不触发用户文件迁移。
- 设置模型只增加有默认值的字段时才提升设置版本；本版本优先使用代码常量，不变更设置格式。
- 持久化断点包含完整计划，文件可能较大，但只保留一份。
- 后台安全角监控必须在退出时可靠取消，避免窗口销毁后回调。
- 单实例对象名称需要包含用户标识，避免不同 Windows 用户会话互相影响。
- Release 工作流不得将签名证书或密码写入仓库和日志。

## 验收标准

- 10ms 点击间隔下，界面进度更新不超过每秒 10～12 次，停止请求在正常系统负载下 200ms 内送达执行引擎。
- 执行中关闭窗口不会在窗口消失后继续运行点击任务。
- 强制结束进程后重新启动，可以发现并恢复有效断点。
- 同一用户启动第二实例时，不创建第二主窗口，并激活已有窗口。
- 连续触发延时记录只新增一个点位。
- 大量点位空闲编辑时不再持续重复序列化草稿。
- 日志超过限制后自动删除最旧文件。
- `dotnet test` 或仓库测试脚本实际执行全部测试，不允许零测试假通过。
- 安装版、便携版、说明文档和校验文件均标记为 `2.1.0`。
